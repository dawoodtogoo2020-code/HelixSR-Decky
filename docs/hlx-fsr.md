# HLX FSR 4 on SteamOS

Decky 0.1.37 added **HLX FSR 4 (FSR 4.1.2 Lite)** to the game details screen and the standalone desktop UI; the 0.1.38 release keeps it and fixes review findings. The base is Decky 0.1.36. There is one reviewed HLX model, not separate HLX 4.0 and HLX 4.1 downloads. The default Model E / HelixSR 2.0.0 selection is unchanged.

**0.1.38 changes:** the status monitor reads HLX's CRLF log lines and reports every AMD fallback the reviewed DLL logs (including a failed own-runtime build and an explicit FSR version request), and no longer reports a deliberately selected AMD-native Scaler output as a fallback. Choosing HLX for one game no longer preselects it for the next uninstalled game. An unmanaged HLX drop-in or stray `.amd.dll` beside the game's FSR DLL now blocks direct installation of any model. Switching an HLX game back to Model E explains that **Remove** comes first.

| Choice | What it controls |
| --- | --- |
| HLX FSR 4 | HelixSR's implementation of the AMD FSR 4.1.2.4555 Lite model; the reviewed 3.2.0 prerelease supplies the finished runtime. |
| AMD FSR (native) in Scaler | AMD's separate SDK provider. Its DLL version is 4.1.2; the available algorithm depends on the GPU, driver and game. It can run an older FSR path. |
| AMD FSR, DLSS or XeSS in the game | Input route. The in-game label alone cannot establish which output provider ran. |
| Frame generation | Independent of SR. The 3.2 package has no HelixSR Light/Full FG. Scaler's FSR FG and XeSS FG require game and hardware support. The existing 2.0 options remain available on 2.0; earlier Steam Deck/PRAGMATA tests reported flicker and poor performance. |

**Install on a Steam Deck or other x86-64 SteamOS device**

1. Close the game and wait for Steam downloads to finish. In Decky's settings, enable developer options if necessary, then install **HelixSR-Decky-0.1.38.zip** using the ZIP installer. The install ZIP contains the plugin, not game runtimes or weights. If you use both interfaces on one library, update both before managing this model. Do not use the published older desktop app to manage an HLX install. The desktop UI is included in the source archive; from the source directory with the dependencies in desktop/requirements-build.txt installed, run `python3 -m desktop.app` as the regular user.
2. In the game details choose **HLX FSR 4 (FSR 4.1.2 Lite)**, and confirm **HelixSR 3.2.0 (pre-release, HLX FSR 4 only)**. Review the upscaler, route, changed files and licenses. For Model E or HelixSR FG, keep the **2.0.0** selection. Do not use “Latest upstream” as a substitute for the reviewed package. An incompatible or replaced archive must not be installed.
3. **Direct:** Requires the game's original x64 split `amd_fidelityfx_upscaler_dx12.dll`. The plugin saves its bytes in the companion folder and makes the runtime's `.amd.dll` fallback from those bytes. Select **AMD FSR** in the game. This route installs SR only and needs no DXGI launch override. A monolithic `amd_fidelityfx_dx12.dll` alone is insufficient. If an unmanaged mod already supplies the original, fallback or receipt, restore it with its owning manager first. Do not delete someone else's backup to get past a conflict.
4. **Scaler:** Select the Scaler route before installing in an unmanaged, compatible DX12 game with a detected FSR, DLSS or XeSS input. Follow the game's guidance (including any game-specific loader requirements). On Proton the DXGI proxy normally needs `WINEDLLOVERRIDES="dxgi=n,b" %command%`; merge with existing launch options and overrides instead of replacing them. In the game select the supported input; in the plugin's per-game settings select HLX or AMD-native output and restart the game. For an upgrade from 2.0, switch an active HelixSR FG configuration to Off, FSR or XeSS first. Retained custom FFX DLL paths or conflicting installations can block migration. Changing between direct and Scaler requires restoring/removing the old route first.
5. **Rollback:** Close the game. **Disable** restores the original files and keeps the record for **Enable**; **Remove** restores them and retires the installation record. **Repair HelixSR files** recreates only absent, reproducible owned files from the exact verified package; it will not overwrite externally changed files. For an interrupted operation, use **Recover** before another install. Keep `<game folder> Mod Files/HelixSR-Decky/` (next to the game), including `records/`, `originals/` and any `transaction/`, until recovery completes. A changed Steam build or backup requires review. Restore the game through the managing build before reverting to Decky 0.1.36.

**What to verify on the target device**

There is no gameplay, FPS or hardware-compatibility claim for Steam Deck, other SteamOS devices or PS5 Linux in this build. File and GUI tests run without a game renderer. PS5 Linux testing is deferred.

- Record device/GPU, SteamOS, Mesa and Proton versions, game/build, executable, power limit, display/internal resolution and quality preset. Back up the relevant save/settings, use an offline single-player scene or built-in benchmark and keep a clean baseline. Do not inject into anti-cheat games. Start with all FG off.
- Compare the baseline and HLX at the same settings, then compare AMD-native in Scaler if supported. Use a repeatable moving route and at least three measured runs per setting after warm-up. Collect frametimes (median and 95th percentile), crashes and visible defects such as flicker, ghosting, broken UI or frames with incorrect color. Record motion, not just menus or static images.
- Match the process/module to the installed provider and use a **fresh** HLX log. **Direct:** HLX writes `HLX_FSR.log` beside the DLL it loaded, or into an existing `OptiScaler.log` in that folder. Some games load their DLLs from a mirror folder such as `_storage_`. **Scaler:** with OptiScaler's file log off (as installed), HLX writes `OptiScaler/HLX_FSR.log`. With `LogToFile=true` under `[Log]` in the game's `OptiScaler.ini`, its lines go to `OptiScaler.log`; for the status monitor also set `LogLevel=2` (Info), because the default Trace level grows too fast. Turn file logging off for benchmarks. Distinguish HLX's own-runtime context creation from delegated AMD fallback. A context message is not dispatch proof; use a GPU frame capture or another provider-specific dispatch trace for the actual rendered frames. Note that captures can affect timing; benchmark separately. If FG is tested, keep SR fixed and report frame-generation evidence separately.
- Close the game, disable, re-enable and remove, verifying the original game DLL digest and pre-test settings. Mark a run inconclusive if you cannot attribute the rendered output. A later PS5 Linux run must pass these checks independently; it does not prove Steam Deck compatibility.
